# 艺人改版验收记录

日期：2026-10-04。实现工作区：现有 `codex/artist-profile-discography` 分支。没有合并其他工作区、提交、发布或部署。测试账本均创建于系统临时目录，未使用个人收藏数据。

## 已采用的规则

- 有效 artist MBID 去重后只剩一个候选，自动保存 `single`；跳过额外作品/别名请求。
- 多候选逐一核对本地作品标题与 artist-credit。唯一有证据且其余探测未失败时保存 `corroborated`；无法区分才人工 `manual`。
- 旧单候选缓存直接采用；旧多候选缓存重新核对。新增、删除或修改本地专辑标题后，多候选证据缓存失效。
- 自动匹配不改本地艺人字段。身份和实物副本-作品关联分别处理，后者仍需确认。绑定方式随现有备份保存，无 schema 迁移。
- 独立艺人入口覆盖库存任意排序/列表/卡片、售出中、交易、在途及详情；脏表单摘要和回收站入口保持原有规则。
- 桌面宽抽屉分栏 + 封面网格；手机整屏 + 小封面纵向列表，更多别名/类型与来源管理按需展开。确认区使用独立底栏，正文让出真实空间。

## 浏览器验证

使用项目 CLI、临时数据目录与 `--no-seed` 启动实际构建产物。两类实例分开：可控 MusicBrainz fixture 负责确定状态与副本流程；真实公开 MusicBrainz/CAA 实例负责完整来源链路。fixture 封面为明确的测试占位图片。

- 桌面视口 1280、1440、1024；手机视口 390、360、320。正文无横向溢出，长艺人/作品名正常换行；320px 小封面 56px，其余手机目录 64px。明暗主题均检查。
- 普通库存列表的独立艺人列、手机双列卡片、同专辑 `span 2` 副本组可用；艺人点击不会勾选副本或误开专辑详情。
- 售出中、已交易、在途页面的艺人入口均实际点击并打开资料；全模块 fixture 的艺人摘要正确显示持有 4 / 售出中 1 / 曾收藏 1。
- 两个虚构 Atlas 同名候选显示数量、类型、地区、区分说明、专辑核对状态；radio 实际宽高均 18px。候选来源另有独立核对链接。选择后确认区在底栏，聚焦搜索框后仍位于正文可见区域。
- Nirvana 两候选 fixture 通过本地 Nevermind 自动确定身份，显示“已用本地专辑确认”；空结果保留本地收藏并提供重新搜索。
- 分类切换、确认/取消关联、展开本地副本、打开详情及返回走通；返回保留 EP 分类、副本展开和滚动。Esc 关闭，焦点返回原艺人按钮。通用详情聚焦关闭按钮。
- 正常关键流程及真实公开来源实例浏览器 error 日志为零。
