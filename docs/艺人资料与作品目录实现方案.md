# 艺人资料与作品目录：Agent 实现指导

日期：2026-10-02。状态：实现方案，尚未实现。

用户要求：放弃以 RYM 自动访问和搜索跳转作为主路径；点击艺人名称后，在碟渡中查看艺人信息及生涯作品；**不要使用 Wikipedia**。本次交付是指导文档，不执行产品代码改动、发布或部署。

实现前完整阅读根目录 `AGENTS.md`，查阅 `AI开发复盘.md` 中 RYM、身份匹配、作品与版本、网络缓存、抽屉叠层相关案例。本文规定该功能的目标行为；金额、模块、独立副本、数据安全及部署规则仍以 `AGENTS.md` 和用户最新要求为准。

## 1. 交付目标与首版范围

主流程：**库存按艺人分组 → 点击艺人名称 → 艺人资料抽屉 → 按发行年份浏览作品 → 查看与自己的收藏关联的副本**。

首版完成以下内容：

1. 艺人结构化资料：官方记录名称、别名、艺人类型、关联地区、出生/成立等日期、音乐类型、MusicBrainz 来源入口。
2. MusicBrainz 作品目录：按作品分组，展示名称、首次发行日期、类型和封面。
3. 在碟渡内处理少数同名候选，保存确认后的艺人身份；支持纠正错误绑定。
4. 展示“我的收藏”，区分确认关联、名称匹配建议和未关联；保留每张实物副本。
5. 缓存、分页、缺失资料、网络失败和重启后复用。
6. 退役 RYM 搜索/书签入口，保留历史绑定数据及备份能力。

资料来源固定为 **MusicBrainz API + Cover Art Archive（CAA）**。现有 iTunes 录入/封面功能继续使用原流程；新艺人目录首版不新增 iTunes 查询。

不调用 Wikipedia API，不抓取或嵌入 Wikipedia 页面，不通过 Wikidata/Wikimedia 间接补充资料，不展示其简介或图片。首版也不增加 LLM 传记生成、艺人照片抓取、评分榜单、试听播放器、追踪新发行或全库后台扫描。

## 3. 艺人资料的内容口径

资料面板以可核对的事实为主，不显示传记式长文。没有数据的字段隐藏；整个概况缺失时显示“该艺人的详细资料暂未收录”，作品目录仍可独立展示。

| 字段 | 显示规则 |
|---|---|
| 标题 | 保留用户库内名称；来源名称不同时在下面显示“资料名称：…” |
| 类型 | Person 显示“个人艺人”；Group 显示“组合”；其他类型显示可靠映射或来源原值 |
| 别名 | 原文保留；默认最多 3 个，其余展开；不覆盖库内名称 |
| 地区 | 用“关联地区”，不将国家/区域字段解释为国籍 |
| Person 的 life-span | 显示“出生 / 逝世”；不可写成活跃年份、出道年份或职业生涯 |
| Group 的 life-span | 显示“成立 / 解散”；缺少结束日期时不推断仍在活动 |
| 其他类型的 life-span | 有明确语义才显示，否则保留数据但不展示 |
| genres | 用“音乐类型”；缺失则隐藏，不从作品标题或当地流行风格猜测 |
| disambiguation | 主要用于候选区分；存在时作为简短补充，不称为人物简介 |
| 来源 | MusicBrainz 艺人页入口、资料更新时间；来源链接新标签页打开 |

日期保留来源精度：`2000`、`2000-03`、`2000-03-31` 均有效，不补成虚假的 1 月 1 日。最早收录作品的年份不等于出道年份。

首版不显示艺人照片，不用专辑封面冒充艺人头像。名称和结构化资料承担页头信息。

## 4. 点击与界面行为

### 4.1 打开入口

首版替换 `ShelfPage.tsx` 的艺人分组标题入口，不顺带把所有卡片和副本详情中的普通艺人文字改成交互入口。

使用 `button type="button"`，复用现有 `.artist-name` 的字体和视觉层级，移除外跳箭头。可访问名称为“查看 {艺人名} 的资料与作品”。鼠标、Enter、Space 均可打开；关闭后焦点回到原按钮。

抽屉打开立即展示名称与本地收藏，不等待外网。外部资料在抽屉内加载，不能阻塞 `/api/state`、保存副本或正常导航。

### 4.2 资料抽屉结构

顺序固定：

1. 艺人名称与结构化概况。
2. “我的收藏”摘要，按作品关联展示持有、售出中、曾收藏的数量。
3. 分类切换：“专辑 / EP / 单曲 / 现场 / 精选 / 其他”，默认“专辑”。
4. 按首次发行日期升序排列的作品列表：小封面、作品名、日期、类型补充、收藏关联状态。
5. 未关联的本地副本，可折叠查看。
6. 来源更新时间、“更新资料”和“更换艺人”次要操作。

作品采用紧凑列表，首版不增加卡片/列表偏好。手机分类可横向滚动，每个选项均可到达；长名称换行，日期与状态不遮挡名称。复用 `Seg` 等已有控件与主题 token。

不使用买入月份时间轴，不重排库存页面，不改变当前库存筛选、布局偏好、勾选或底部批量浮条。

### 4.3 打开副本与返回

展开作品可查看确认关联的独立副本，使用现有状态文案及版本/碟盒/侧标信息。点击副本进入既有 `openDetail()`，替换当前抽屉，提供“返回艺人资料”。

通过可选返回回调保存艺人名、分类与列表位置；不要为此引入抽屉栈或新的导航体系。`components/` 仅接收回调，不能反向 import `forms/`。

实物照片灯箱仍按既有机制工作，Esc 只关闭最顶层。返回或更换内容时，现有脏表单退出保护必须继续生效。

### 4.4 必须实现的状态

| 状态 | 文案与行为 |
|---|---|
| 首次加载 | 本地收藏可见；“正在查找艺人资料…” |
| 多个候选 | “有多位同名艺人，请确认”；展示名称、地区、类型和与本地专辑相关的证据 |
| 无候选 | “资料库暂未找到该艺人”；保留本地收藏，可重新搜索名称 |
| 部分目录 | “已读取 N / M 项作品”；继续读取剩余页，失败后可从该页重试 |
| 已读取完整目录 | 显示“资料库收录 N 项作品”；不写“完整生涯”或保证实际发行全收录 |
| 当前分类为空 | “当前分类暂无收录作品”；其他分类仍可切换 |
| 网络失败且无缓存 | “暂时无法连接资料库”；可重试，本地收藏仍可使用 |
| 网络失败且有缓存 | 保留内容，显示“当前显示缓存资料”和更新时间 |
| 封面不存在/失败 | 使用既有缺图样式；不影响文字、排序或作品状态 |
| 绑定的 MBID 已失效 | 保留原绑定，标为“资料身份需重新确认”；进入更换艺人流程 |

资料来源可能缺失；不能把“查询失败”“仅读取部分页”和“确实无收录”合并成空目录。

## 5. 艺人身份匹配

### 5.1 身份保存

艺人身份使用 MusicBrainz artist MBID。库内艺人名是本地入口，不是外部唯一身份。

绑定保存在现有 `meta` 的 `artist-identities-v1`：

```json
{
  "Example Artist": {
    "artistMbid": "00000000-0000-0000-0000-000000000000",
    "sourceName": "Example Artist",
    "method": "manual",
    "confirmedAt": "2026-10-02T00:00:00Z"
  }
}
```

这是格式示意；全零 UUID 不可用作实际绑定。实际值必须来自通过验证的 MusicBrainz 响应。

`method` 只能由服务端确定为 `manual` 或 `corroborated`。用户手动确认的绑定优先；迟到的自动解析不能覆盖它。不同库内名称分别绑定，首版不自动合并别名对应的本地分组。

### 5.2 解析规则

1. 已有有效绑定时直接使用，不重复搜索名称。
2. 名称召回使用 MusicBrainz artist 搜索，并正确进行 Lucene 转义与 URL 编码。
3. 对返回候选按有效 artist MBID 去重。仅一个有效候选时直接保存 `method: single`，无需名称或作品证据请求；本地艺人字符串保持原样。
4. 多个候选时核对全部已返回身份：用去重后的本地作品标题检索 release-group，验证标题与 artist-credit 中的 MBID。唯一候选有证据、其余核对未失败时保存 `method: corroborated`；相同名称共享查询结果。
5. 无证据、并列或任何候选探测失败时返回 ambiguous，展示实际数量及核对状态，允许人工绑定（manual）。单候选旧缓存立即按新规则采用，多候选旧缓存重新核对。

搜索最多返回 10 位候选，证据检索尝试 2 个去重本地标题，35 秒预算含节流与网络。来源 count 大于已返回数量或核对失败时 `evidenceComplete: false`；来源截断不阻止已返回候选中作品证据唯一的绑定。

这些规则用于艺人身份映射，不改记录署名，也不自动确认具体压片、版次或实物副本的作品关联。

候选允许“调整搜索名称”；搜索名称不写回本地记录。选择候选后，先显示“将库内 {A} 对应到资料库 {B}”及区分资料，再点击“确认艺人”。

## 6. 作品目录与分类

### 6.1 作品级身份

目录主键使用 **release-group MBID**。同一作品的 CD、数字、黑胶、各地区和再版归到一项。不得把 release ID 当作作品 ID，也不得因为作品名相同就合并两个不同 release-group。

目录不按 CD 介质过滤：用户要浏览生涯作品，作品可能从未发行 CD。是否为自己持有的具体 CD 版本，是副本/发行资料的另一层问题。

目录读取接口使用 artist MBID 的 release-group browse，采用 `release-group-status=website-default`。保留来源主类型、次类型、artist-credit 与 first-release-date。此筛选不能被文案解释为“所有作品都已验证是正式发行”。

### 6.2 分类规则

每项仅进入一个主分类，原始次类型继续以标签保留。优先级固定：

1. 次类型含 Compilation → 精选。
2. 否则次类型含 Live → 现场。
3. 否则存在其他次类型，例如 Remix、Soundtrack、Demo、Interview → 其他。
4. 否则主类型 EP → EP；Single → 单曲；Album → 专辑。
5. 其他或未知主类型 → 其他。

因此带 Compilation + Live 的作品归精选，同时显示“现场”标签。无附加类型的 Album 显示为“专辑”，不要擅自证明它是录音室录音。缺少类型的作品仍必须保留。

### 6.3 分页与排序

每页最多 100 项；按实际返回数量推进 offset，不以艺人 lookup 内附的最多 25 项充当整个目录。客户端分批读取，按 MBID 去重。

一次页请求最多发起一个 MusicBrainz 目录网络请求。来源 count、实际条数和分页进度均保留。尚未读取完时显示部分状态；重复页、空页但 count 未达、count 变化等情况停止自动推进并显示可重试状态，不能无限循环。

只有全部页成功且唯一作品数量与该轮来源 count 一致，才能将该轮结果标为 `complete: true`。这只表示读取了来源当次返回的目录，不证明现实中的发行史完整。

完整结果按日期升序；缺少日期放末尾，同日按标题、MBID 稳定排序。部分结果先按同规则展示，补页可能改变位置；不能将第一页宣称为该艺人的最早作品。

## 7. 与本地收藏关联

### 7.1 独立关联与建议

当前 `ReleaseInfo` 没有确定的 MBID，所以首版采用**单独的副本—作品关联**。不修改历史副本名称、版本、购买数据或现有发行资料。

保存在 `meta.record-work-links-v1`，每个 record ID 最多对应一个作品：

```json
{
  "example-record-id": {
    "artistMbid": "00000000-0000-0000-0000-000000000000",
    "releaseGroupMbid": "11111111-1111-1111-1111-111111111111",
    "recordArtist": "Example Artist",
    "recordTitle": "Example Album",
    "method": "manual",
    "confirmedAt": "2026-10-02T00:00:00Z"
  }
}
```

示例 ID 不是有效记录。保存时服务端核验真实 record ID、绑定艺人、作品 artist-credit 与快照字段。关联只说明“此副本属于该作品”，不确认首版、压片、介质或具体发行版本。

用户可在作品展开区“关联我的副本”，从该本地艺人的未关联记录中选择；逐张保留身份，重复副本可以关联到同一作品。取消关联只删除该关联，不移除副本。

本地标题严格匹配且只命中该艺人一个作品时，可提示“可能已收藏 · N 张”，展开查看建议；必须由用户点击“确认关联”才能变成确定关联。模糊/前缀匹配仅供候选，不能标为已收藏。未有关联时显示“未关联”，不显示“未收藏”。

### 7.2 数量与记录变化

确认关联且不在回收站的副本按当前状态分别统计：

- `domestic`、`overseas`、`transit` → 持有。
- `shipping` → 售出中。
- `sold` → 曾收藏。
- `trash` → 不计入面板收藏数量。

多个状态可同时出现，持有与曾收藏不能互相覆盖。模块关闭时按 `core/modules.ts` 既有口径显示状态；关联功能属于基础收藏，不依赖购入、交易或周转模块。

记录名称/艺人发生变化，或艺人绑定被更换时，旧关联变为“需重新核对”，不继续计入确定关联。金额、笔记、存放位置变化不应使作品关联失效。

旧关联可保留供用户重新确认；回收站恢复可以恢复有效关联。不存在的记录 ID 在展示时忽略，不能因绑定读取而复活或创建记录。

## 8. 后端设计与接口契约

### 8.1 文件职责

- 新增根模块 `musicbrainz.py`：纯标准库 MusicBrainz HTTP 客户端与实例级统一节流；不创建模块级服务或发起 import 时网络请求。
- 新增 `server/artists.py`：`ArtistService`，负责艺人解析、资料归一、目录分页、公共资料文件缓存、CAA 目录封面。
- `storage.py`：本地记录读取、绑定/关联校验后的事务保存、审计、备份恢复校验。所有账本数据库写入在这里。
- `server/context.py`：增加可选 `artists` 服务；`app.build()` 组装共同的 MusicBrainz 客户端并注入 covers、vision、artists。
- `server/routes.py`：仅处理参数、调用服务、短时间写锁与响应；禁止在 `server/http.py` 添加具体业务接口。

### 8.2 对碟渡的 API

路径是本方案的目标契约；不要复用语义不同的旧 `/api/artist-bind`。

| 方法 / 路径 | 输入 | 返回与副作用 |
|---|---|---|
| POST `/api/artists/resolve` | `{artist, searchName?}` | `resolved / ambiguous / not_found / unavailable`、候选及证据；单候选或多候选专辑证据唯一时保存自动绑定 |
| POST `/api/artists/bind` | `{artist, artistMbid, expectedArtistMbid}` | 核验后保存人工绑定；当前绑定与预期不符返回 409 |
| GET `/api/artists/profile?artist=...` | 本地名称；可选 `refresh=1` | 绑定、归一化资料、本地收藏、缓存状态；无绑定返回 `needs_resolution` |
| GET `/api/artists/catalog?artist=...&offset=0` | 本地名称、offset；可选 `refresh=1`、`roundId` | 一页作品、来源 count、nextOffset、roundId、分页/缓存状态 |
| POST `/api/artists/work-link` | `{artist, recordId, releaseGroupMbid, expectedReleaseGroupMbid, recordArtist, recordTitle}` | 核验后保存单张副本关联；快照或原关联变更返回 409 |
| POST `/api/artists/work-unlink` | `{recordId, expectedReleaseGroupMbid}` | 删除该条关联；预期不符返回 409 |
| GET `/api/artists/artwork/<releaseGroupMbid>` | 已在本地目录缓存中出现的作品 ID | 验证后的缩略图片；无图 404、临时失败 503 |

profile/catalog 的读取规则：默认先返回已有缓存；无缓存时读取来源；显式 `refresh=1` 才跳过尚有效的缓存。旧缓存响应带 `refreshSuggested: true`，前端在当前抽屉中后台刷新。

新绑定/关联不存在时，`expectedArtistMbid` / `expectedReleaseGroupMbid` 显式传 null；更换时传当前 ID。目录首个刷新请求由服务端生成 `roundId`，后续分页带同一个 roundId，不反复以 `refresh=1` 新建刷新轮次。过期轮次返回 409，可重新开始；有旧完整目录时继续显示旧列表，只展示新轮次加载进度，待新轮次完整后一次替换。

所有新接口沿用登录、Origin 与 Host 校验，不进入 `PUBLIC_GET` 或 `CROSS_SITE_POST`。接收本地艺人名时校验字符串长度 1–500，且属于已有记录；UUID 严格校验，不接受任意 URL、主机或文件路径。

网络请求不持有 `WRITE_LOCK` 或账本事务。网络核验完成后，在短写锁内重新读取当前记录/绑定、校验预期再执行 storage 方法。自动保存只允许填补未绑定入口，禁止覆盖人工绑定。

业务结果用 JSON 状态表示；输入错误 400，未登录 401，竞争导致过期 409。远端临时失败无可用资料时用 503；有旧缓存则 200 并明确标记来源失败和缓存状态。不得把解析异常包装成 `not_found`。

### 8.3 前端数据模型

在 `web/src/core/artists.ts` 定义稳定类型与请求封装，组件消费归一化对象，不读取 MusicBrainz 原始 JSON：

```ts
type CatalogCategory = 'album' | 'ep' | 'single' | 'live' | 'compilation' | 'other';
type ResolutionStatus = 'resolved' | 'ambiguous' | 'not_found' | 'unavailable';
type CacheState = 'fresh' | 'stale' | 'missing';

interface ArtistProfile {
  mbid: string;
  name: string;
  aliases: string[];
  type: string | null;
  area: string | null;
  lifeSpan: {begin: string | null; end: string | null; ended: boolean | null};
  genres: string[];
  disambiguation: string | null;
  sourceUrl: string;
}

interface ArtistWork {
  mbid: string;
  title: string;
  firstReleaseDate: string | null;
  primaryType: string | null;
  secondaryTypes: string[];
  category: CatalogCategory;
  artistMbids: string[];
  artworkUrl: string | null; // 仅碟渡自己的图片 API
  sourceUrl: string;
}

interface SourceState {
  fetchedAt: string | null;
  cache: CacheState;
  refreshSuggested: boolean;
  error: string | null;
}
```

目录页另有 `artistMbid`、`roundId`、`offset`、`returned`、`total: number | null`、`nextOffset: number | null`。整体视图另维护 `complete`；`total` 未知时不可显示 0。艺人、目录和封面分别管理加载/错误状态。页数据只归入相同 artistMbid 和 roundId 的列表。

通过既有 `core/api.ts` 扩展可选 AbortSignal 或使用组件请求序号；关闭、更换艺人、重新解析时，迟到响应不能覆盖新视图或重新打开抽屉。API 扩展必须保持现有调用的默认行为。

## 9. MusicBrainz 请求、缓存与封面

### 9.1 来源调用

使用官方 JSON API：

```text
GET https://musicbrainz.org/ws/2/artist?query=<escaped>&fmt=json&limit=10
GET https://musicbrainz.org/ws/2/artist/<MBID>?inc=aliases+genres&fmt=json
GET https://musicbrainz.org/ws/2/release-group?artist=<MBID>&inc=artist-credits&release-group-status=website-default&limit=100&offset=<N>&fmt=json
```

标题证据检索使用 release-group search，客户端核查返回 artist-credit，不能仅相信查询匹配。请求参数均由服务端构建，来源 JSON 作为数据处理，不渲染来源 HTML。

MusicBrainz 要求客户端每秒最多一次请求，并标识 User-Agent。为此所有现有和新增 MusicBrainz 实际网络调用共用同一实例节流，间隔采用 1.1 秒；命中缓存不等待。[官方 API 规则](https://musicbrainz.org/doc/MusicBrainz_API)

现有 covers 和 vision 的各自局部锁不构成全应用节流。只将它们的 MusicBrainz HTTP 路径接入共同客户端，保持原缓存、候选、返回字段及错误口径，避免顺带重写其他封面来源。

每次 HTTP 请求超时 10 秒，JSON 响应上限 4 MiB；只允许 HTTPS `musicbrainz.org` 的固定 API，拒绝跨主机重定向。429/503 尊重合法 Retry-After，在共同客户端记录冷却时间，冷却期间返回可重试状态，不让 HTTP 线程长时间睡眠；无缓存时交给用户重试。首版不增加长期任务队列或无限自动重试。

### 9.2 公共资料缓存

缓存保存到数据目录下的 `artist-cache/`，文件由 `ArtistService` 管理，使用 UTF-8 JSON 与临时文件 + 原子替换。不要新建由 service 直接写的 SQLite 缓存库。

缓存采用 artist/作品 MBID 及受控请求参数命名，不使用用户输入作为路径。记录来源、请求参数、`fetchedAt`、归一化版本、页 count 与内容；艺人资料/目录有效期 7 天。

旧完整目录在新一轮刷新完成前保留；不要先清空旧目录。每轮刷新分开归集页，只有该轮完整校验后才替换完整快照，不混用不同刷新轮次的页宣称完成。刷新期间和失败时可继续显示旧完整快照及更新时间。

名称未命中可缓存 1 小时；临时网络失败只做 60 秒请求抑制，不能保存为长期“无此艺人”。缓存损坏时忽略损坏文件并重建，不影响绑定、账本或应用启动。

相同艺人资料/相同目录页的并发请求合并，防止同一次点击产生重复外网请求。所有锁、请求状态和缓存索引属于服务实例；测试可注入 opener、时钟及等待函数，不依赖真实睡眠。

`artist-cache/` 是可重建缓存，不纳入账本 JSON 备份，不写入 `settings`，不进入 `/api/state` 的全量负载。用户确认的两个 meta 映射随现有完整备份保存。

### 9.3 目录封面

优先展示已确认关联的本地副本封面；没有时按 release-group 查询 CAA 缩略封面。仅在作品进入可见区域时请求，最多 2 个并发封面加载；不得为整个人生目录启动全量图片下载。

CAA 使用组级代表封面，文案不能声称这是用户持有的 CD 版封面。保留其来源；不覆盖任何副本现有封面。[CAA API](https://musicbrainz.org/doc/Cover_Art_Archive/API)

图片经碟渡自身 artwork API 返回，文件缓存到 `artist-cache/artwork/`。复用现有允许的 CAA/Archive 主机与 JPEG/PNG/WebP 内容验证，限制 2 MiB、重定向次数和最终来源；来源无图与暂时不可用分别缓存/响应。

无图负缓存 1 天，临时图片失败抑制 60 秒；成功图片缓存 30 天。前端失败后显示占位，不无限重试。不新增前端外网 connect-src，也不放宽 CSP。

## 10. 持久化、恢复与 RYM 退役

两个新 meta 键通过 `storage.py` 的事务写入，并记录“确认艺人 / 更换艺人 / 关联作品 / 取消作品关联”审计。持久化的映射不包含外网缓存正文。

恢复可能带来不存在的本地记录/已过期关联；按第 7 节在读取时处理，不篡改其他资料。新缓存目录按现有 `data/` 忽略规则隔离。
